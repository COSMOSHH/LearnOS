## 1. 总体结论

最新一轮 `20260506_165249` 的 **latest 模式已经超过原始 RAG**，整体指标有小幅但明确的正向提升：

- **MRR：0.9762 → 0.9779，提升 +0.0017**

1. **Quiz / 填空类问题路由误伤**；
2. **短 query 改写过度具体化**；
3. **药品 / 品牌类实体被错误泛化为常规药物问题**。

一句话总结：

> 最新版 RAG 已经从“上下文增强版”进入“指标正收益版”。下一步不应继续大幅调整主链路，而应做小范围失败样本修复，重点处理 quiz、短 query 和实体类 rewrite guard。

## 6. 最新版主要回归样本

最新版相对原始版有 4 条明显回归：

| Query | 原始 RR | 最新 RR | 回归 | 主要原因 |
|---|---:|---:|---:|---|
| 什么围棋填合适的词 | 1.0 | 0.0 | -1.0 | quiz 改写过度，原始 query 信息被稀释 |
| 小辣椒和什么最和适 | 1.0 | 0.25 | -0.75 | 短 query 被强行改写成食材搭配 |
| 易香有副作用吗 | 1.0 | 0.3333 | -0.6667 | “易香”被泛化为药物实体，Top1 被不相关药物抢占 |
| 国考笔试成绩要比分数线高多少才能考上 | 1.0 | 0.5 | -0.5 | interview/考试类改写过宽，排序从 top1 降到 rank2 |

### 6.1 Quiz 类回归：`什么围棋填合适的词`

原始版该 query 是 top1 命中，但最新版改写为：

```text
围棋中填空题应填写的合适词语或术语
```

这个改写看似语义更完整，但实际引入了“填空题”“术语”等额外语义，可能稀释了原始 query 的字面匹配信号。该样本最终变成 no_hit，是当前最严重的回归。

建议：

- quiz 类不要默认改写为抽象描述；
- 保留原 query 作为主查询；
- 改写 query 只能作为辅助 query；
- 对“什么 X 填合适的词”类 pattern，优先 literal / BM25 / ngram。

### 6.2 短 query 过度具体化：`小辣椒和什么最和适`

最新版改写为：

```text
小辣椒适合搭配什么食材或食物
```

问题在于：

- `最和适` 只需要修正为 `最合适`；
- 不应额外加入“食材或食物”；
- 如果语料中是种植、颜色、人物昵称或其他语境，会导致召回偏移。

建议：

- 对短 query 开启 conservative rewrite；
- 只修错别字，不加领域假设；
- 改写后必须保留核心 token：`小辣椒`、`最合适`。

### 6.3 实体泛化错误：`易香有副作用吗`

最新版改写为：

```text
易香药物的不良反应或副作用有哪些
```

问题在于：

- “易香”未必一定是药物；
- 即使是药品 / 产品，也应保留品牌名的精确匹配优先级；
- 改写成“药物的不良反应”后，容易召回通用药物副作用内容，导致相关结果排到第 3 位。

建议：

- 对未知短实体 + “副作用”类 query，不要直接泛化为药物；
- 使用 `entity_exact_boost`：实体名必须参与 BM25 / exact matching；
- query rewrite 可生成辅助表达，但不能替代原 query。

## 8. 下一步优化建议

### P0：Quiz 类 query 必须保留原 query 为主查询

当前 `什么围棋填合适的词` 从 top1 回归到 no_hit，说明 quiz 路由风险较高。

建议策略：

```text
如果命中 pattern：什么 + X + 填 + 合适的词
则：
1. 原 query 权重最高；
2. 改写 query 仅作为扩展；
3. BM25 / literal / ngram 权重大于语义扩展；
4. 禁止引入“填空题”“术语”等抽象泛化词作为主查询。
```

### P0：短 query conservative rewrite

针对 8 个字以内、实体明确但语境不足的 query：

- 只做错别字修正；
- 不添加领域；
- 不添加用途；
- 不把实体强行归类为食物、药物、品牌、影视等。

示例：

| 原 query | 推荐改写 | 不推荐改写 |
|---|---|---|
| 小辣椒和什么最和适 | 小辣椒和什么最合适 | 小辣椒适合搭配什么食材或食物 |
| 易香有副作用吗 | 易香有副作用吗 | 易香药物的不良反应有哪些 |

### P1：literal_riddle 不只靠 BM25

`欲钱买春光灿烂打一肖` 已经走 `literal_bm25_heavy`，但仍 no_hit，说明 BM25 top_k=20 还不够。

建议补充：

- char ngram 检索；
- query 字符级相似度；
- 对 `打一肖` / `打一生肖` / `欲钱买` 等 pattern 使用 dedicated retriever；
- 保留原 query，不做语义扩展覆盖。

### P1：实体精确匹配加权

对以下模式使用实体 exact boost：

```text
{短实体} + 有副作用吗
{短实体} + 怎么样
{短实体} + 是什么
{短实体} + 好不好
```

重点是不能让改写后的泛化词压过实体本身。

### P2：interview / 考试类问题避免目标漂移

`国考笔试成绩要比分数线高多少才能考上` 从 top1 降到 rank2，说明改写后的“进入面试或被录用”可能扩大了问题范围。

建议：

- 保留原始关键词：`国考`、`笔试成绩`、`分数线`、`高多少`、`考上`；
- 不要把“考上”过度解释为“进入面试或被录用”；
- 对考试类 query，避免引入流程性解释词覆盖原始分数判断意图。
