# LearnOS RAG产品功能清单与优先级

## 1. 目标定义

这份清单只聚焦 LearnOS 的 RAG 能力建设，不覆盖测验、复习、学习计划、学习报告等全局学习系统能力。

目标是把当前 LearnOS 的检索问答，从“可用的混合检索”逐步升级成：

1. 可解释
2. 可观测
3. 可评测
4. 可持续调优
5. 更贴合学习场景的 Advanced RAG

---

## 2. 版本节奏

### `RAG V1.1`

聚焦低成本高收益优化：

1. Query Rewrite
2. 标题增强分块
3. 检索调试可视化

状态：`已完成`

### `RAG V1.2`

补齐 Advanced RAG 主体能力：

1. Multi-Query / 子问题分解
2. Parent-Child 多粒度检索
3. 上下文压缩 / 去重 / 裁剪

状态：`已完成`

### `RAG V1.3`

补齐检索评测闭环：

1. 检索评测集
2. Recall@k / MRR / Top-k 命中统计
3. 低质量 query 分析
4. 前端 RAG 评测页

状态：`已完成（第一版）`

说明：
- 已支持默认评测集与按当前学习会话自动生成评测 case。
- 已支持在前端直接运行评测并查看指标和低质量 query。
- 更大规模的评测样本库、按资料类型分桶统计和长期趋势看板仍属于后续增强。

### `RAG V2`

补齐学习场景差异化能力：

1. 问题类型识别与检索路由
2. 面试模式专属检索策略
3. RAG 质量看板

状态：`已完成（第一版）`

说明：
- 已支持按事实、对比、原因、总结、面试、计划、测验等问题类型选择不同检索路由。
- 已支持动态调整 Multi-Query、top-k、Parent 回填窗口和上下文预算。
- 已支持低质量 query 样本沉淀与前端 `RAG质量` 看板。

## 5. V1.3 具体交付内容

这次 `RAG V1.3` 第一版已经实际落地了以下内容：

1. 新增默认评测集文件 `rag_eval_cases.json`
2. 新增 `services/rag_eval_service.py`
3. 支持根据当前学习会话自动生成评测 cases
4. 支持后端直接运行检索评测并输出：
   - `MRR`
   - `Recall@1 / Recall@3 / Recall@5`
   - `Top-k 命中情况`
   - `low_quality_cases`
5. 新增接口：
   - `GET /study_sessions/{session_id}/rag/eval_dataset_template`
   - `GET /study_sessions/{session_id}/rag/eval_cases`
   - `POST /study_sessions/{session_id}/rag/evaluate`
6. 前端新增 `RAG评测` 标签页，可直接：
   - 预览评测集
   - 运行评测
   - 查看指标
   - 查看低质量 query
   - 查看每条 case 的检索调试信息
7. 服务层和接口层测试已覆盖 RAG 评测主链路

## 6. 为什么 V1.3 标注为“已完成（第一版）”

因为当前完成的是一个可运行、可验证、可展示的第一版闭环，而不是最终形态。

已经具备：

1. 评测 case
2. 自动运行评测
3. 指标输出
4. 低质量 query 定位
5. 前端展示
6. 自动化测试

但还没做到：

1. 更大规模的评测样本库
2. 按资料类型、问题类型分桶统计
3. 长期趋势跟踪
4. 面向产品的综合 RAG 质量大盘

所以最准确的口径是：`RAG V1.3 已完成第一版，可继续增强。`

---

## 7. 近期建议

如果下一轮只做 3 件事，建议是：

1. 扩大评测样本库并做跨会话趋势
2. 按资料类型、问题类型输出更细分桶
3. 把学习计划和测验生成也接入专属检索增强

如果下一轮再多做 3 件事，建议补：

1. 面试报告和追问策略继续增强
2. RAG 质量看板增加跨日期趋势
3. 把低质 query 样本反向生成评测 case

---

## 8. 一句话结论

LearnOS 的 RAG 当前状态可以表述为：

`V1.1 已完成，V1.2 已完成，V1.3 第一版已完成，V1.2 后续优化已完成第一版，RAG V2 的“检索路由 + 质量看板”已完成第一版。`
