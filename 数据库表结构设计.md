# 学习辅助 Agent 数据库表结构设计

## 1. 设计目标

数据库设计需要支持以下能力：

1. 管理学习会话和文档。
2. 管理知识点、复习项、测验记录。
3. 管理用户历史对话和线程状态。
4. 支持自动复习、错题回流和学习计划。
5. 为后续 Agent 工作流、评测和执行日志扩展留接口。

当前项目已使用 SQLite，因此第一阶段继续采用 SQLite，后续可平滑迁移到 PostgreSQL。

## 2. 设计原则

1. 会话与文档分离。
2. 原始数据与结构化抽取结果分离。
3. 聊天历史与学习记忆分离。
4. 复习项、错题、测验结果可互相关联。
5. 字段尽量兼容 SQLite，避免第一阶段过度设计。

## 4. 表结构设计

### 4.1 `users`

说明：
如果目前只有单用户，也建议预留这张表，后续可以用于演示多用户隔离能力。

```sql
CREATE TABLE users (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id TEXT NOT NULL UNIQUE,
    display_name TEXT,
    target_role TEXT,
    preferences_json TEXT,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

关键字段：

1. `user_id`
   对外用户标识。
2. `target_role`
   目标岗位，例如 `agent_application_engineer`。
3. `preferences_json`
   存储学习偏好、难度偏好、复习偏好。

### 4.2 `study_sessions`

说明：
表示一次学习批次，通常对应“今天的学习”或“某个主题学习任务”。

```sql
CREATE TABLE study_sessions (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id TEXT NOT NULL,
    session_name TEXT NOT NULL,
    topic TEXT,
    goal TEXT,
    status TEXT DEFAULT 'active',
    session_date DATE,
    tags_json TEXT,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

建议索引：

```sql
CREATE INDEX idx_study_sessions_user_date
ON study_sessions(user_id, session_date);
```

### 4.3 `study_documents`

说明：
记录用户上传的原始学习资料。

```sql
CREATE TABLE study_documents (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    session_id INTEGER NOT NULL,
    title TEXT NOT NULL,
    file_name TEXT,
    file_path TEXT,
    file_type TEXT,
    file_size INTEGER,
    content_hash TEXT,
    ingest_status TEXT DEFAULT 'pending',
    source_type TEXT DEFAULT 'upload',
    metadata_json TEXT,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY(session_id) REFERENCES study_sessions(id)
);
```

建议索引：

```sql
CREATE INDEX idx_study_documents_session_id
ON study_documents(session_id);

CREATE INDEX idx_study_documents_content_hash
ON study_documents(content_hash);
```

### 4.4 `document_chunks`

说明：
记录文档切片元数据。向量本体仍存 Chroma，这张表用于保存结构映射和查询辅助信息。

```sql
CREATE TABLE document_chunks (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    document_id INTEGER NOT NULL,
    chunk_index INTEGER NOT NULL,
    chunk_text TEXT NOT NULL,
    token_count INTEGER,
    chroma_doc_id TEXT,
    metadata_json TEXT,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY(document_id) REFERENCES study_documents(id)
);
```

建议索引：

```sql
CREATE INDEX idx_document_chunks_document_id
ON document_chunks(document_id);

CREATE INDEX idx_document_chunks_chroma_doc_id
ON document_chunks(chroma_doc_id);
```

### 4.5 `document_summaries`

说明：
存储文档级摘要结果，便于快速回显和复用。

```sql
CREATE TABLE document_summaries (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    document_id INTEGER NOT NULL,
    summary_type TEXT NOT NULL,
    summary_text TEXT NOT NULL,
    extra_json TEXT,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY(document_id) REFERENCES study_documents(id)
);
```

`summary_type` 推荐取值：

1. `short_summary`
2. `core_concepts`
3. `keywords`
4. `interview_takeaways`

### 4.6 `knowledge_points`

说明：
把学习材料中的重要知识点结构化保存，用于问答、复习、测验和进度分析。

```sql
CREATE TABLE knowledge_points (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    session_id INTEGER NOT NULL,
    document_id INTEGER,
    title TEXT NOT NULL,
    description TEXT,
    category TEXT,
    importance INTEGER DEFAULT 3,
    difficulty INTEGER DEFAULT 3,
    source_chunk_id INTEGER,
    status TEXT DEFAULT 'active',
    metadata_json TEXT,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY(session_id) REFERENCES study_sessions(id),
    FOREIGN KEY(document_id) REFERENCES study_documents(id)
);
```

建议索引：

```sql
CREATE INDEX idx_knowledge_points_session_id
ON knowledge_points(session_id);

CREATE INDEX idx_knowledge_points_document_id
ON knowledge_points(document_id);
```

### 4.7 `review_items`

说明：
自动复习的核心表，第一阶段非常关键。

```sql
CREATE TABLE review_items (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id TEXT NOT NULL,
    session_id INTEGER,
    knowledge_point_id INTEGER,
    topic TEXT NOT NULL,
    summary TEXT NOT NULL,
    source_type TEXT,
    review_status TEXT DEFAULT 'new',
    confidence_score INTEGER DEFAULT 3,
    error_count INTEGER DEFAULT 0,
    review_count INTEGER DEFAULT 0,
    last_reviewed_at DATETIME,
    next_review_at DATETIME,
    priority_score REAL DEFAULT 0,
    metadata_json TEXT,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY(session_id) REFERENCES study_sessions(id),
    FOREIGN KEY(knowledge_point_id) REFERENCES knowledge_points(id)
);
```

建议索引：

```sql
CREATE INDEX idx_review_items_user_next_review
ON review_items(user_id, next_review_at);

CREATE INDEX idx_review_items_session_id
ON review_items(session_id);
```

### 4.8 `chat_history`

说明：
沿用当前项目已有设计，但建议新增 `session_id` 以便把问答与学习会话关联。

```sql
CREATE TABLE chat_history (

```

## 6. 第一阶段最小必做表

如果第一阶段希望控制范围，建议只落下面 7 张表：

1. `study_sessions`
2. `study_documents`
3. `document_chunks`
4. `document_summaries`
5. `knowledge_points`
6. `review_items`
7. `chat_history`

`thread_state` 当前已经有了，可以直接复用。

## 10. 总结

第一阶段的数据设计重点不在“大而全”，而在能支撑这三件事：

1. 管理当天学习资料。
2. 管理结构化复习记忆。
3. 管理问答与学习会话的关联。

只要这三件事跑通，后续无论是测验、计划还是执行日志，都能自然扩展上去。
