# 学习辅助 Agent 数据库表结构设计

## 1. 设计目标

数据库设计需要支持以下能力：

1. 管理学习会话和文档。
2. 管理知识点、复习项、测验记录。
3. 管理用户历史对话和线程状态。
4. 支持学习报告与后续错题、计划扩展。
5. 为后续 Agent 工作流、评测和执行日志扩展留接口。

当前项目已使用 SQLite，因此当前版本继续采用 SQLite，后续可平滑迁移到 PostgreSQL。

## 2. 设计原则

1. 会话与文档分离。
2. 原始数据与结构化抽取结果分离。
3. 聊天历史与学习记忆分离。
4. 测验题集与测验作答分离。
5. 字段尽量兼容 SQLite，避免当前阶段过度设计。

## 4. 当前实际表结构

以下内容优先对应当前 `tools/init_db.py` 的真实实现。

### 4.1 `study_sessions`

```sql
CREATE TABLE study_sessions (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id TEXT NOT NULL,
    session_name TEXT NOT NULL,
    topic TEXT,
    goal TEXT,
    status TEXT DEFAULT 'active',
    session_date DATE,
    tags_json TEXT,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

用途：

1. 表示一次学习批次或一个学习主题容器。
2. 既支持空白会话，也支持导入资料时自动创建的会话。

索引：

```sql
CREATE INDEX idx_sessions_user_date
ON study_sessions(user_id, session_date);
```

### 4.2 `study_documents`

```sql
CREATE TABLE study_documents (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    session_id INTEGER NOT NULL,
    title TEXT NOT NULL,
    file_name TEXT,
    file_path TEXT,
    file_type TEXT,
    file_size INTEGER,
    content_hash TEXT,
    ingest_status TEXT DEFAULT 'pending',
    source_type TEXT DEFAULT 'upload',
    metadata_json TEXT,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

说明：

1. `source_type` 当前实际用于区分 `upload` 和 `webpage`。
2. `metadata_json` 当前会保存 `source_url`、`site_name` 等网页来源信息。

索引：

```sql
CREATE INDEX idx_documents_session_id
ON study_documents(session_id);
```

### 4.3 `document_chunks`

```sql
CREATE TABLE document_chunks (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    document_id INTEGER NOT NULL,
    chunk_index INTEGER NOT NULL,
    chunk_text TEXT NOT NULL,
    token_count INTEGER,
    chroma_doc_id TEXT,
    metadata_json TEXT,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

说明：

1. 向量正文仍存 Chroma。
2. SQLite 里主要保留切片文本、映射关系和元数据。

索引：

```sql
CREATE INDEX idx_chunks_document_id
ON document_chunks(document_id);
```

### 4.4 `document_summaries`

```sql
CREATE TABLE document_summaries (
    id INTEGER PRIMARY KEY AUTOINCREMENT,

    summary_text TEXT NOT NULL,

```

`summary_type` 当前主要使用：

1. `short_summary`
2. `keywords`
3. `interview_takeaways`

### 4.6 `review_items`

```sql
CREATE TABLE review_items (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id TEXT NOT NULL,
    session_id INTEGER,
    knowledge_point_id INTEGER,
    topic TEXT NOT NULL,
    summary TEXT NOT NULL,
    source_type TEXT,
    review_status TEXT DEFAULT 'new',
    confidence_score INTEGER DEFAULT 3,
    error_count INTEGER DEFAULT 0,
    review_count INTEGER DEFAULT 0,
    last_reviewed_at DATETIME,
    next_review_at DATETIME,
    priority_score REAL DEFAULT 0,
    mastery_level REAL DEFAULT 0,
    last_score REAL DEFAULT 0,
    best_score REAL DEFAULT 0,
    retry_count INTEGER DEFAULT 0,
    metadata_json TEXT,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

说明：

1. 当前 `review_items` 不只是“待复习条目”，也是复习调度的核心数据源。
2. `mastery_level`、`last_score`、`best_score`、`retry_count` 已用于复习优先级计算和错题状态演进。

索引：

```sql
CREATE INDEX idx_review_user_next_review
ON review_items(user_id, next_review_at);
```

### 4.7 `quiz_sets`

```sql
CREATE TABLE quiz_sets (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    session_id INTEGER NOT NULL,
    title TEXT NOT NULL,
    question_count INTEGER DEFAULT 3,
```

1. 一条记录表示一次整套测验。
2. 当前题集是按学习会话组织，而不是单独按 `user_id + topic` 组织。
3. `metadata_json` 可扩展保存生成参数、题目说明等附加信息。

索引：

```sql
CREATE INDEX idx_quiz_sets_session_id
ON quiz_sets(session_id);
```

### 4.12 `study_plans`

```sql

    session_id INTEGER NOT NULL,

    title TEXT NOT NULL,

    status TEXT DEFAULT 'active',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,

```

说明：

1. 一条记录表示某个学习会话的一版已保存学习计划。
2. `source_type` 当前主要使用 `generated` 和 `reprioritized`。

### 4.13 `study_plan_items`

```sql
CREATE TABLE study_plan_items (
    id INTEGER PRIMARY KEY AUTOINCREMENT,

    item_type TEXT NOT NULL,

    sort_order INTEGER DEFAULT 0,

    metadata_json TEXT,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP

```

说明：

1. 一条记录表示学习计划中的一个动作项。
2. `item_type` 当前主要覆盖“今天学什么 / 先复习什么 / 下一步问什么 / 行动步骤”等计划分类。
3. `is_completed` 当前用于前端勾选完成状态和“只看未完成项”筛选。
4. `priority_score` 当前用于动态重排学习计划优先级。

## 6. 当前删除策略

删除学习会话时，当前服务会同步清理以下数据：

1. `quiz_attempts`
2. `quiz_questions`
3. `quiz_sets`
4. `study_plan_items`
5. `study_plans`
6. `wrong_question_attempts`
7. `answer_evaluations`
8. `interview_turns`
9. `interview_sessions`
10. `agent_run_steps`
11. `agent_runs`
12. `event_logs`
13. `review_items`
14. `knowledge_points`
15. `document_summaries`
16. `document_chunks`
17. `study_documents`
18. `study_sessions`

另外：

1. `chat_history` 中该会话的历史也会清理。
2. `thread_state` 中对应线程状态也会清理。
3. Chroma 向量库中该会话的向量切片也会清理。

## 7. 当前代码映射

1. `tools/init_db.py`
   初始化 `study_sessions`、`study_documents`、`review_items`、`quiz_*` 等学习数据表。
2. `services/study_session_service.py`
   负责学习会话的增删改查，以及删除时的级联清理。
3. `services/document_service.py`
   负责文档、切片、摘要、知识点持久化。
4. `services/quiz_service.py`
   负责混合题型测验生成、题目存储、作答评分、最近一次测验读取。
5. `services/report_service.py`
   负责把资料、问答、测验和复习项汇总成学习报告。
6. `services/plan_service.py`
   负责基于知识点、复习项、问答和测验结果生成学习计划，并负责学习计划的保存、加载、完成状态更新与动态重排。
7. `services/review_service.py`
   负责复习优先级调度、错题重练、复习状态演进与复习上下文构造。
8. `services/observability_service.py`
   负责关键动作事件日志，以及 `agent_runs / agent_run_steps` 的写入与查询。
9. `Zero_RAG/chat_history_service.py`
   继续负责 `chat_history` 和 `thread_state`。
10. `services/evaluation_service.py`
   负责学习问答与模拟面试回答的质量评测、评测结果保存与聚合。
11. `services/interview_service.py`
   负责模拟面试 blueprint 生成、会话创建、逐轮作答、总结生成。

## 8. 后续预留扩展

当前仍建议为下一阶段保留这些扩展方向：

1. 学习计划增强

3. 模拟面试增强
   当前 `interview_sessions` 和 `interview_turns` 已落地，下一步更适合补更智能的追问策略和面试报告。
4. 可观测增强
   当前 `agent_runs` 和 `agent_run_steps` 已落地，下一步更适合补聚合统计、告警与趋势视图。

## 9. 总结

当前版本的数据设计重点不再只是“支撑导入和问答”，而是已经能支撑这些能力：

1. 管理学习资料与学习会话。
2. 管理结构化知识和复习记忆。
3. 管理会话内问答历史。
4. 管理整套测验与学习复盘结果。
5. 管理可保存、可勾选的学习计划。
6. 管理错题重练与状态演进。
7. 管理学习问答与模拟面试的回答质量评测。
8. 管理模拟面试会话与逐轮问答。
9. 管理事件日志以及 Agent run / step 级运行观测。

这套结构已经足够支撑当前 LearnOS 的可演示主链路，也给后续错题、计划和评测留出了自然扩展空间。
